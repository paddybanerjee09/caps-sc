# UI and interaction decisions

## Current conventions

- The always-on UI requirements are in `.cursor/rules/ui-style-guide.mdc`. `cb31dff` introduced contrast and spacing tokens in `src/theme/theme.ts`. Use `useAppTheme()`, bordered screen-owned form sections, and tabular numeric readouts. The 20 November audit replaces the rejected weight/time steppers with decimal fields and a shared time modal, and standardizes subscreen navigation through `WorkflowChrome`.
- `src/utils/feedback.ts` centralizes semantic cues and synthesizes tones. `5c595dd` added it and hooked up navigation chrome. `feedbackSelection`, `feedbackStep`, `feedbackToggle`, `feedbackConfirm`, `feedbackWarn`, `feedbackCountdownTick`, and `feedbackPhaseCue` serve distinct events. Settings updates separate audio and haptic flags. `PressOpacity` can be silent when the caller issues its own cue. Existing small primitives include `SimpleSwitch` and `LogTimeChanger`.
- `LogTimeChanger` grew out of the July weight/sleep/date-time work (`3232443`, `859b4aa`, `d94e5c3`). The former full-card and increment-button variants are removed. Every caller now gets a compact clock/time button opening the same Log Time modal with local-day arrows and independent 24-hour/minute scroll wheels. Cancel leaves the timestamp unchanged; Done applies the current wheel position, including during momentum, subject to caller bounds.
- `c8ddb63` replaced deprecated `InteractionManager` in Home and Nutrition loads with `src/utils/scheduleIdleTask.ts`. Its cancelable idle callback has a timer fallback. Cancel outstanding loads when their key changes or a screen unmounts. `6ccb251` adjusted Nutrition dependencies to keep unrelated workspace updates from reloading the diary. `17e5a94` derives Conditioning load status from its fetch key.
- Conditioning editors, the Create Session chooser, emphasis help, and confirmation overlays have explicit exceptions defined in `.cursor/rules/navigation-and-overlays.mdc`. The saved-workout expander is the deliberate layout-pushing control. See [[Conditioning]] for entry points and state.

## Historical decisions

- The September training lineage experimented with shared adaptation displays, generic collection states, responsive tile grids, timeline presenters, and a shared modal frame (`44d4e27`, `9a39461`–`6f5d88d`, `7fac1fb`). A nested virtualized action menu was fixed before actions were switched to full-width buttons (`741e5a8`, `009aff6`, `95b4fa1`). The lineage is preserved at `origin/backup/pre-revert-7daf5e7`. [[Project History]] explains the rollback and [[Strength]] covers the archived implementation.
- Earlier November design rules required steppers/presets and prohibited shared chrome. The 20 November user correction supersedes those rules: weight/load uses decimal input, log times use one modal picker, and subscreen bars share their implementation. Compare active components before borrowing any archived UI.

Evidence is linked in the [Architecture tree](../../docs/feature-tree/architecture.html#style-guide) under style guide, shared controls, feedback, idle tasks, and the shared-UI archive.

## Shared main-screen title card (20 November 2026)

`src/components/ScreenTitleCard.tsx` extracts the Strength banner unchanged: full-height theme accent, left-aligned 26px/800 title, 13px/18px subtitle, 16px vertical padding. Home and Nutrition use it through `Screen`; Strength, Conditioning and Skill use it directly. The user explicitly requested this shared component, an exception to the general screen-local wrapper rule. `Screen.centerTitle` was removed after checking its only callers (Home and Nutrition). Commit `43eab3a`; Home caller updated in `548bbe5`.

Bottom tab labels (20 November 2026, `52d6ba2`): `src/components/BottomTabs.tsx` uses a shared 9px font / 11px line height for all five tabs, reduced from 10px / 12px to address Conditioning wrapping. Incremental desktop Arial bold measurements including 0.2px tracking: 10px = 63.85px, 9.5px = 60.76px, 9px = 57.68px against 61.2px available at 360px viewport. This is a proxy, not native font evidence; device bridge failed to start. Keep font scaling enabled and the existing two-line allowance for Skills Training.

## Uniform subscreens and inputs (20 November 2026)

- `src/components/WorkflowChrome.tsx` owns `WorkflowHeader` and `WorkflowFooter`. The header accounts for the top safe area, centers its title between equal side widths, puts branch-wide X at left, and accepts a compact log-time trigger at right. Home overlays pass `topInset={0}` because the existing app header already accounts for it. Footer navigation says Cancel at depth one and Back deeper; existing domain actions remain next to it outside scroll content. Bottom tabs own the bottom system inset.
- Domain stacks retain custom state navigation. Strength/Conditioning branch-close methods preserve their draft/session guards; Nutrition closes layers while preserving its persisted drafts; Skills retains its builder discard guard. Footer Back preserves parent drafts and pops one level. Sidebar routes use `Screen.onClose/footer`, hide the global header, and return to the previously active main tab; Account and Athlete Information register their close guards for system Back as well.
- Every bodyweight, resistance/load, assistance and added-weight field uses a decimal text box without fine/coarse adjustments or preset strips. Nutrition serving/macro fields also use direct decimal input. Useful count, RPE, activity-duration, age/height and categorical controls are retained. No repository/schema change is part of this audit.
- `src/utils/numericInput.ts` validates complete finite decimal entries, including comma decimal keyboards. `src/utils/logTime.ts` handles local-day changes, labels, and date bounds. Shared time selection uses existing React Native controls, without adding a native dependency.
- Source audit coverage, findings, and verification limits are recorded in [[2026-11-20 UI Audit Review]] and [[2026-11-20 Uniform Logging and Navigation Handoff]]. Native visual/interaction verification remains separate from static/type/domain checks.
