## Uniform subscreens and inputs (20 November 2026)

- `src/components/WorkflowChrome.tsx` owns `WorkflowHeader` and `WorkflowFooter`. The header accounts for the top safe area, centers its title between equal side widths, puts branch-wide X at left, and accepts a compact log-time trigger at right. Home overlays pass `topInset={0}` because the existing app header already accounts for it. Footer navigation says Cancel at depth one and Back deeper; existing domain actions remain next to it outside scroll content. Bottom tabs own the bottom system inset.
- Domain stacks retain custom state navigation. Strength/Conditioning branch-close methods preserve their draft/session guards; Nutrition closes layers while preserving its persisted drafts; Skills retains its builder discard guard. Footer Back preserves parent drafts and pops one level. Sidebar routes use `Screen.onClose/footer`, hide the global header, and return to the previously active main tab; Account and Athlete Information register their close guards for system Back as well.
- Every bodyweight, resistance/load, assistance and added-weight field uses a decimal text box without fine/coarse adjustments or preset strips. Nutrition serving/macro fields also use direct decimal input. Useful count, RPE, activity-duration, age/height and categorical controls are retained. No repository/schema change is part of this audit.
- `src/utils/numericInput.ts` validates complete finite decimal entries, including comma decimal keyboards. `src/utils/logTime.ts` handles local-day changes, labels, and date bounds. Shared time selection uses existing React Native controls, without adding a native dependency.
- Source audit coverage, findings, and verification limits are recorded in [[2026-11-20 UI Audit Review]] and [[2026-11-20 Uniform Logging and Navigation Handoff]]. Native visual/interaction verification remains separate from static/type/domain checks.

## Background music and feedback (20 November 2026)

`29c5ad2` fixes feedback sounds interrupting Spotify. The SDK 58 Android module starts with a null interruption mode, which requests transient audio focus; explicitly selecting `mixWithOthers` maps to no focus request. `src/utils/feedback.ts` now shares and awaits that configuration before creating/playing any cue on either platform. Haptics still fire immediately. Configuration failure skips audio and permits retry; disabling audio during initialization suppresses pending cues. Keep mixing as a feedback invariant. Typecheck, targeted ESLint, and mocked runtime checks passed; Spotify/device acceptance remains unverified. See [[2026-11-20 Background Audio Feedback Handoff]].
