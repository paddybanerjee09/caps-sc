# Recovery and Progress

Recovery and Progress are implemented under the existing [[Home]] segmented navigation, with code-level verification and native acceptance still open. Implementation/report: `docs/recovery-progress.md`; original specification: `docs/recovery-progress-spec.md`; native setup: `docs/recovery-native-setup.md`.

- `src/recovery/` contains the current-day lifecycle, questionnaire form, accessible controlled ratings, dual clock/date controls, SRI v1, objective calculations and daily biometric cards. No measured physiological value is invented; missing values render -- and ORI retains its experimental title.
- `src/data/recoveryMigration.ts` adds SQLite v10. `recoveryRepository.ts` owns local-owner-scoped active questionnaire identity, immutable saved revisions, atomic health/cursor upserts, source preferences, daily snapshots and comparable baselines. See [[Data and Persistence]]. Existing weight/timeline rows are queried directly; planned sleep is not measured sleep.
- `src/health/` uses actual read-only native bridges with lazy Expo Go fallback, anchors/change tracking, source-aware sleep and upstream deletion handling. Device permission/linking tests have not run. HRR60 and skin temperature deviation remain unavailable without their required comparable inputs.
- `src/progress/` implements weight, indices, cardiac, sleep and fatigue groups with calendar periods, source/version separation, broken lines, top legends, synchronized date tooltips and coverage-aware means. Experimental CAPS ORI v1 is enabled for eligible native biometric data.
- Baseline decisions: prior 28 calendar days, minimum 14 comparable days, exclude current date, sample SD and zero-variance suppression, lnRMSSD only for RMSSD. SRI v1's equal weights/awakening cap are app-defined, not Hooper/validated readiness. Mood is chart-only.
- Existing Home timezone-free weight rows follow current device timezone; native/questionnaire records retain captured day/timezone. Supplied native UTC offsets are retained as fixed zones without an invented IANA location, and sleep uses its wake-ending source zone/session boundary. Historical questionnaire edits preserve the original timezone; clocks explicitly display device timezone after travel. Full date fallback supports unusual sleep and explicit repeated DST-hour selection.

Verification passes: TypeScript, full ESLint, eight verification commands (four existing domains + recovery/input/health/progress), native config/dependency checks and both platform JS/Hermes bundle exports. Production acceptance remains open for physical iOS/Android builds/permissions/sensors, gestures/keyboard/large fonts, years-of-records profiling, real bundle IDs, retention/security and privacy navigation. Optional notifications are deferred. No authenticated account/backend exists; all data remains device-local. No scientific readiness validation claimed.

Feature Tree ownership: Home recovery/progress nodes, Database v10 table nodes and Architecture health adapter node. See [[2026-11-21 Recovery and Progress Handoff]] for commits, evidence and remaining actions.

## CAPS-owned ORI v1 (22 November 2026)

The user's explicit follow-up requests a CAPS-owned biometric score rather than vendor scores. This supersedes the historical unconfigured-ORI default above. `src/recovery/objectiveRecovery.ts` implements `caps_ori_v1`: 40% HRV,30% RHR,30% measured sleep; all three need 14 comparable prior days/28-day window. Missing inputs remain blank with per-contributor reasons. Source/subtype identities and model version partition history. See docs/caps-ori-v1.md for every transform, noise floor, limitation and JSON persistence/rollback explanation. No SQL migration or added permissions/dependencies. Not independently validated or percent recovered.

## Minimal display (22 November 2026)

User correction: default screens should be concise and compact. Recovery cards show one short definition/requirement and -- for missing values, without status/baseline/provenance paragraphs. Questionnaire instructions, scoring footers and redundant hints are removed; necessary anchors, dates/timezones, errors and draft guards remain. Health sources/disconnect/delete remain under Manage. Progress uses Choose graph with Body Weight / Recovery Indices / Cardiac Indices / Sleep Indices / Fatigue Indices, existing timeframes, compact period/refresh controls and date/value/unit inspection. Stored model, source, coverage and raw records remain intact; no scoring or schema change. Current copy contract: .cursor/rules/ui-style-guide.mdc section9.
