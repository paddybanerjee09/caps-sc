# Strength History

Archived September 14–25 v1 only. See [[Strength]] for current status. The tip is `origin/backup/pre-revert-7daf5e7` (`7daf5e7`) and its shared ancestor with main is `e8fc8e9`, the parent of the October 2 `9fc0f73` commit. The Feature Tree records the development reset and leaves the rationale unknown. Historical files below can be inspected with `git show 7daf5e7:<repository-path>`.

| Area | Archived design and evolution |
| --- | --- |
| Screen and month | `179a443` wired calendar, saved-workout and create/log entry points, with Strength sessions projected into `DayTimeline` and `timelineRepository`; `ac17683` checked integration and reload. `44d4e27` shared `src/components/MonthTimeline.tsx` and `AdaptationScoreDisplay` with Conditioning v1. `ba0759f` used category colors in the day timeline and contextual adaptation resolvers for month views. |
| Saved and read-only workflows | `d319861` introduced the saved dropdown and `LogStrengthSessionConfirmationModal`. `da78b5b` added `StrengthSessionDetailModal` for reading immutable logged sessions. `6f5d88d` switched saved workouts to a modal and added `SessionActionMenu` / `SessionActionTile`. `278eb96` restored inline saved workouts and `e330adc` shared `SavedSessionCardGrid`. `741e5a8` fixed nested virtualized menus before actions became stacked full-width controls (`009aff6`, `95b4fa1`, `3f5a8e7`). |
| Create and prescribe | `acea2c3` created the template/quick-log modal. `9de04e0` added `ExerciseSearchModal`, `StrengthExerciseEditorModal`, and form primitives for sets, reps, load, and RPE. `beaf2d3` aligned log-time controls. `c6a334a` compacted exercise logging. `9a39461` separated and normalized ExerciseDB types and formatting, `c32cb6b` added compact rows and shared collection states, and `a9b40d1` / `59a1b23` adopted shared `AppModalFrame` and adaptation-status UI. The current style guide calls for screen-local cards and ordinary screens for entry. |
| SQLite and snapshots | `e8b22c1` added `src/data/strengthMigration.ts` and `strengthRepository.ts`. Historical migration v10 had template headers and ordered template exercises. The repository copied prescriptions into immutable logs keyed by `timeline_entries.id`. Deleting a source template could null its link while preserving logs. Session and exercise scoring had separate tables. Repository inserts allowed external exercise ID and a user-confirmed label while excluding provider anatomy, instructions, and media from stored exercise snapshots. Main's active migration v7 is a different lineage. |
| Exercise search | `b270cdf` implemented `src/services/exerciseDbApi.ts`, and `018d898` corrected its then-current free endpoint and cancellation handling. The archived adapter treated free search as a single returned list, distinguished an aborted caller from a network timeout, filtered obvious cardio, and supported a separate configuration for a first-party proxy. `9a39461` introduced `src/types/exerciseDb.ts` and `src/utils/exerciseDbFormatting.ts`. A new integration should verify today's upstream contract. |
| Estimates and evidence | `1154954` introduced `src/utils/strengthSessionDraft.ts`, `strengthScoring.ts`, and `strengthMovementProfile.ts`. Scoring estimated independent hypertrophy, power, and endurance contributions from workload, reps, RPE, intensity evidence, and movement intent. It used curated verified IDs or conservative label rules and left other movements unknown. The `44d4e27` adaptation UI showed evidence. Archived tests in `86922a9` and `51e011a` cover schema/log persistence and score/movement evidence on that lineage. |

Historical UI specs and their tests are visible in `5ca254f`, `2933434`, `f0c6cc0`, and `090a944`. The audit branch `feat/ui-redesign-audit` merged into the archived line in `7fac1fb`. These tests were inspected through the tree and commit history during backfill. They were not run against the archived source. For the historical tree nodes, use [[Feature Tree Crosswalk]].
