## Logging

`src/state/SkillWorkspaceContext.tsx` keeps the session draft, search query and raw activity-form strings while the composer, activity picker or editor is open, including tab switches. Its fixed footer always shows **Save** or **Unsave**, alongside Cancel and Log. Save immediately writes a reusable template; a matching saved fingerprint shows Unsave. Editing template fields shows Save until the existing template is updated. Unsave immediately archives the template and detaches the draft; the next Save creates a new template ID. The mutation lock blocks repeated actions, edits and exits while writes are pending; failures keep the draft and saved state available for retry.

Save uses the existing relational tables: `skill_templates.id` owns the ordered `skill_template_activities.template_id` rows. Saving an existing linked template replaces those activity rows in one transaction; Unsave sets the template's `archived_at` without deleting prior logs. Log remains a separate transaction writing `skill_sessions`, independent activity snapshots and their estimator version, and a `timeline_entries` row of kind `skill`. The session ID makes a log retry a no-op. Schema v11 extends activity snapshots for reps without altering template/session header ownership. See the persistence detail below.

Time is stored in epoch milliseconds and seconds. `started_at` is the chosen end minus elapsed seconds. `local_end_date` is the device-local date of that end, so a session that crosses midnight is placed on the day it finished. `timezone` is the IANA zone captured at commit. Templates store no date or time. Reopening one sets Ends at to the current time.

Numeric RPE is optional, stored as null when omitted and never zero. An entered RPE maps to the existing estimate bands: 1–6 easy, 7–8 moderate, 9–10 hard. Band-only legacy entries retain their stored band; a new activity starts with the established moderate estimate basis. Sparring and rolling also store a separate mode. Legacy Duration uses the entered seconds as work and zero rest and is preserved until explicitly edited. The new editor offers Reps/Rounds; an existing Duration entry is presented as one round of the original work time, with zero rest, if the user chooses to apply that editor. Rounds use `rounds × seconds per round` as work and `(rounds − 1) × rest` as rest, so one round with a configured rest stores that rest and adds no rest seconds. Focus ignores general activities. One combat discipline sets the focus. Two or more set `mixed`.

Calories are gross kilocalories: `weightKg × ((baseMET × rpeMultiplier × workSeconds) + (1.5 × restSeconds)) / 3600`. The multipliers are 0.80, 1.00, and 1.10. The session stores the unrounded sum, the weight used, `logged` or `reference`, and its estimator version. New logs use `skill-energy-v2-reps`; stored v1 logs and their exact estimates are never recalculated. Reference weight is 75 kg when no `weight_logs` row has a timeline start at or before the end time. `getLatestWeightKg` is unchanged and still returns the newest log with no cutoff.

There is no skill owner table. Conditioning has a singleton owner because those sessions sync. Skill logs stay on the device, as Strength logs do.

`SkillSessionBuilderScreen.tsx` now contains an **Activities** card with **Add Activities** and selected activity rows. `AddSkillActivitiesScreen.tsx` searches all fifteen existing catalog activities; its only bottom action is Back. Selection opens `SkillActivityEditorScreen.tsx`. Add Activity returns directly to the composer; Back removes a new selection or discards local edits with confirmation. X uses the branch-wide discard guard, and pending writes block further actions. There are no parameter steppers, increment/decrement buttons, inline Add Activity chips, or Summary card.

The editor reuses Home's actual `components/nutrition/SegmentedSelector` for **Reps / Rounds** and the same `components/training/TrainingNumberField` used by Strength/Conditioning. Reps has direct Sets, Reps, optional RPE and optional rest-seconds inputs, with Strength's bounds (1–20 sets, 1–100 reps, optional integer RPE 1–10, rest 0–600). Rounds uses direct work seconds, rest seconds, rounds and optional RPE. Sparring/rolling retain their catalog intensity modes. Raw values for both categories remain in the workspace while switching categories; invalid text is retained for correction and never committed.

Rep time is an estimate using the actual pure Strength helper `estimateDurationSeconds`: 3 seconds per rep, omitted rest 90 seconds between sets, explicit zero retained, no rest after the last set. Skills still sums its configured activity blocks without adding an inter-activity transition. This is not measured workout time. Energy applies the existing MET formula to estimated work/rest; the new estimator version records the introduced assumption. Read-only detail uses the stored session/work/rest values rather than recalculating rep time after future assumption changes.

### Schema v11 persistence

`src/data/skillRepsMigration.ts` rebuilds only `skill_template_activities` and `skill_session_activities` in one SQLite transaction. Parent `skill_templates`, `skill_sessions`, and `timeline_entries` rows and all header keys remain unchanged. Existing child primary keys, positions, activity names/types, legacy duration/round inputs, effort bands, and every stored work/rest/MET/multiplier/calorie value copy unchanged. There is no historical estimate recomputation. Interrupted migration rolls back both child tables; retry is safe. The initializer checks both child-column sentinels even if user_version already says 11.

Each child keeps its parent foreign key (`template_id` or `session_id`, with ON DELETE CASCADE) and unique parent/position constraint. The new timing-mode CHECK admits `reps` alongside legacy `duration` and `rounds`. Active-mode fields are explicitly required: reps uses `sets`, `reps`, optional `rest_between_sets_seconds`; legacy duration and rounds keep their original columns. Inactive timing columns are null. The nullable integer `rpe` column preserves the exact numeric target for any mode, while `rpe_band` remains for estimate compatibility.

Save writes a template header and ordered child snapshots transactionally; updating retains the header ID and replaces child rows. Template child IDs remain independent of UI/session IDs. Unsave archives only the template header. Log writes the session header, independent activity snapshots and one unique timeline link in a separate transaction. Rep snapshots persist both configured parameters and the versioned estimated work/rest/calories, so later template edits or heuristic changes cannot rewrite recorded history. Reopened templates restore rep values; old duration and round records remain readable.
