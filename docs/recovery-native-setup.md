# Recovery native health integration

Implemented code is not physical-device validation. These adapters have deterministic JavaScript fixtures; native permission prompts, bridge linking, device data and background behavior require the checks below.

## Installed bridge versions and configuration

The Expo SDK 58 / React Native 0.88 application installs `@kingstinct/react-native-healthkit` 16.2.0, its `@react-native-healthkit/core` dependency, the direct Nitro Modules peer, `react-native-health-connect` 4.1.3, `expo-dev-client`, `expo-constants`, and `expo-build-properties`. Versions are locked in `package-lock.json`; compatibility is inferred from package peer ranges and configuration checks, not an executed native build.

`app.json` configures the HealthKit plugin with read-purpose text, no update-purpose text, and no background delivery. The plugin enables HealthKit entitlements. Android uses the bridge's bundled Expo plugin and `minSdkVersion: 26`; it declares only read permissions for resting heart rate, heart-rate variability, respiratory rate and sleep. No health write, extended-history or background-health permissions are requested. Existing location permissions are unrelated and preserved.

`src/health/healthService.ts` checks Expo Go before evaluating either native bridge and imports only the platform's bridge. Manual Recovery remains available in Expo Go. Native health needs a fresh development build; existing Expo Go or development binaries cannot acquire newly installed modules through JavaScript reloads.

Before building, set the product's actual iOS bundle identifier and Android package name using the project's release setup. None was invented in this change. On a configured native development machine, run `npx expo run:ios` / `npx expo run:android`, or create an EAS development build under the project's existing account/profile. This change does not create an EAS project, choose credentials, submit to stores or publish an app. Windows cannot compile the iOS application locally.

## Data and synchronization contract

- The first authorized read backfills the preceding 28 elapsed days. Android's default historical access limit is respected by keeping this inside the usual 30-day window; no extra history permission is requested. Lifetime charts show the history actually retained by CAPS, not a promise of unrestricted platform history.
- HealthKit imports resting HR in bpm, HRV **SDNN** in ms, and respiratory rate in breaths/min. Native anchors are maintained independently for each quantity and for sleep; only successful queries advance their anchors. Explicit native deletions remove imported observations. Empty HealthKit reads do not prove denial and never clear retained history.
- Health Connect imports `RestingHeartRate`, `HeartRateVariabilityRmssd` (**RMSSD**, ms), `RespiratoryRate`, and stage-bearing `SleepSession` records. A changes token is obtained before backfill, pages are drained, then changes are applied. This prevents edits/deletions during initial backfill being resurrected. Tokens and imported data are persisted together by the repository. Permission changes reset the token; missing permission does not delete retained history. An expired token reports a retryable error and resets the token; the next refresh backfills recent authorized history. Deletions outside that newly visible window cannot be conclusively reconciled after token expiry and may require explicit deletion/reimport of retained history.
- Source app/device identity, native record IDs, native metadata, timestamps and subtype are retained. Manually entered native quantity records are marked unverified. No source averaging is performed. The Recovery source preference and chart grouping are responsible for selecting comparable observations.
- Sleep stage intervals are unioned to avoid double counting. Native Health Connect session identity is preserved. HealthKit supplies stages rather than session identities: stages from the same app/device separated by at most two hours form a candidate session. The longest observed candidate from each source is assigned to its local wake date. This grouping is an explicit implementation choice, not a validated universal sleep-session detector. Other candidates remain in the raw-stage cache for recomputation.
- Only explicitly asleep stages contribute asleep minutes. A bare session window or unknown stage does not become asleep time. Efficiency requires actual in-bed intervals and asleep intervals from the same source; a Health Connect session interval is not assumed to be in-bed time. Therefore many valid native sleep imports have duration but unavailable efficiency.
- Minimal native sleep stages are retained with the cursor in SQLite so upstream edits/deletions can recompute daily duration/efficiency; both raw cache and derived observations are deleted by the explicit delete-imported-data action. The cache grows with observed history and currently recomputes source sleep sessions on each sync. Very long histories need device performance profiling before production scale claims.
- Source timezone metadata is used when the bridge supplies a usable IANA zone. Otherwise the device timezone at import is recorded and explicitly identified as that fallback. Original Android zone offsets are preserved as metadata. Historical local-day assignment for records without source timezone can be uncertain during travel; no missing acquisition zone is invented.
- Heart-rate recovery remains unavailable without a matched standardized exercise/position/recovery protocol. No arbitrary HR sample pair is used. Skin-temperature deviation remains unavailable because the bridges' absolute wrist temperature or within-session temperature deltas do not establish a configured comparable personal baseline. These unused categories are not requested.

The service coalesces concurrent refreshes, stops local import on disconnect, and retains saved observations. Disconnect does not revoke platform permissions or delete data. Explicit imported-data deletion waits for an active sync, disconnects, deletes observations and cursors/raw stages, and prevents automatic reimport until reconnect. HealthKit observer callbacks are foreground opportunities only; Android refreshes on open, foreground and manual refresh. No background refresh guarantee is made.

CAPS currently has one device-local athlete, no authenticated server account and no remote health sync. SQLite storage uses the app sandbox and platform device protection; the app does not add database-level encryption. Neither an authenticated multi-athlete boundary nor encrypted remote persistence is claimed. Never place raw health values in analytics or general error logs.

## Device acceptance procedure (not yet run)

1. Build fresh iOS and Android development clients. Verify manual flow still opens in Expo Go and explains native health unavailability without crashing.
2. On a physical iPhone with real Health data, connect. Confirm only four read categories are requested and no write permission. Grant a subset, then deny/modify one. Verify unavailable values show an em dash without claiming the reason for an empty HealthKit read.
3. Compare source, timestamp, subtype and unit with Apple Health and Health Connect source details. iOS SDNN must stay separate from Android RMSSD. Test two apps/devices writing overlapping samples and explicit source preference.
4. Import real segmented sleep: overlapping stages, unknown stages, missing in-bed data, two sessions in a day, unusual wake time, timezone travel and DST. Check elapsed minutes against source intervals, principal-session assignment and unavailable efficiency where in-bed data is absent.
5. Refresh twice; record counts must not multiply. Add, edit and delete native samples and verify anchors/change tokens update history and derived snapshots. Test edits during initial backfill and a forced expired Android token.
6. Revoke a category, interrupt import/offline storage, resume, retry and inspect prior data retention. A failed partial read must not erase measurements or advance the failing cursor. Check stale dates are not displayed as today's reading.
7. Disconnect: stored history stays, refresh performs no native import. Delete imported data: history/derived values and native sleep cache disappear, questionnaires/weight remain. Reconnect explicitly to reimport.
8. Test Android Health Connect unavailable/provider update, iOS unavailable device, large accessibility text, long error copy, native settings changes and foreground refresh. Validate Android permission rationale/privacy-policy navigation before store distribution; the bridge adds the activity intents but the product privacy-policy destination still needs release integration.
